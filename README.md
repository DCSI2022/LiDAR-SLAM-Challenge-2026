## 🎯 任务说明

参赛者需要基于组织方提供的多传感器 ROS bag 数据，开发鲁棒、可复现的 SLAM 算法，估计传感器连续位姿轨迹，并可根据赛道要求生成一致性较好的三维点云地图。

| 子赛道 | 输入 | 输出 |
| --- | --- | --- |
| **激光惯性 SLAM** | ROS bag 包（激光雷达点云 topic、IMU topic） | 各场景的传感器连续位姿轨迹；可按要求或自愿提交点云地图 |
| **激光-图像-惯性 SLAM** | ROS bag 包（激光雷达点云 topic、IMU topic、同步相机图像 topic） | 各场景的传感器连续位姿轨迹；可按要求或自愿提交点云地图 |

赛道重点考察算法的**定位建图精度、鲁棒性和工程可复现性**。

## 🗂️ 数据集说明

数据集名称为 **Multi-Sensor LiDAR SLAM Challenge Dataset**，以若干实际场景的 ROS bag 包形式发布，包含激光雷达、IMU 和同步相机数据。

## 🚀 参赛流程

1. **提交报名表**：在大赛官网下载报名表，填写后发送至 [lidar2026@126.com](mailto:lidar2026@126.com)。
2. **确认报名**：收到大赛组委会的确认邮件（含数据下载链接）后，即报名成功。
3. **开发与验证**：基于已发布的 ROS bag 包和相关文件完成算法开发、参数调试和本地验证。
4. **生成结果**：处理组织方指定的测评数据，生成各场景对应的轨迹文件。
5. **打包提交**：按本 README 规定的目录结构打包，在截止时间前发送至 [yantaoslam@qq.com](mailto:yantaoslam@qq.com)。
6. **等待评测**：组织方统一评测，并通过大会官网、赛道通知或邮件公布结果。

**提交邮件标题：**

```text
Multi-Sensor SLAM Challenge - 队伍名称 - 子赛道名称
```

> 💡 本赛道采用**离线评测**；若后续调整评测方式，以最新通知为准。

## 📤 提交内容

参赛队应提交单个 `zip` 文件。压缩包中必须包含队伍说明文件和对应子赛道的轨迹文件；地图文件为可选内容，若提交则必须与轨迹文件处于同一坐标系。

**压缩包命名：** `team_name_submission.zip`

### 目录结构

```text
submission.zip
├── README.md
├── lidar_inertial/
│   └── trajectories/
│       ├── scene_0001.txt
│       └── scene_0002.txt
├── lidar_visual_inertial/
│   └── trajectories/
│       ├── scene_0001.txt
│       └── scene_0002.txt
└── maps/
    ├── scene_0001.pcd
    └── scene_0002.pcd
```

| 路径 | 要求 |
| --- | --- |
| `README.md` | **必填**。包含队伍名称、成员、联系方式、参加子赛道、方法简述、运行环境和外部资源使用说明 |
| `lidar_inertial/trajectories/` | 参加激光惯性 SLAM 子赛道时**必填** |
| `lidar_visual_inertial/trajectories/` | 参加激光-图像-惯性 SLAM 子赛道时**必填** |
| `maps/` | **可选**。建议采用 `.pcd` 格式，文件名应与对应场景编号一致 |

只参加其中一个子赛道时，可仅提交该子赛道对应目录。若同一队伍同时参加两个子赛道，应在同一提交包中分别放置两个子赛道的结果。

## 📍 轨迹文件格式

轨迹文件推荐采用 **TUM trajectory** 格式。每个待测场景对应一个 `.txt` 文件，文件名必须与组织方发布的场景编号一致，例如 `scene_0001.txt`。

**每行 8 列：**

```text
timestamp tx ty tz qx qy qz qw
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `timestamp` | `float64` 或 `float32` | 时间戳，单位为秒，应与对应 bag 包时间戳一致 |
| `tx ty tz` | `float64` 或 `float32` | 平移，单位为米 |
| `qx qy qz qw` | `float64` 或 `float32` | 归一化四元数，顺序为 `[x, y, z, w]` |

### 文件要求

- 不得包含 `NaN`、`Inf` 或非数值字段。
- 轨迹行应按时间戳升序排列。
- 不得修改待测数据的原始时间戳。
- 不得缺失要求输出的关键帧或时间戳；若因算法失败无法输出，需在提交包 README 中说明。
- 地图文件如随包提交，应与轨迹使用相同坐标系。
- 单个提交包建议不超过 **500 MB**。

## 📊 评估指标

最终排名以组织方指定测评数据上的主排名指标为准，指标越低表示性能越好。

| 指标类别 | 指标名称 | 说明 |
| --- | --- | --- |
| **主排名指标** | **ATE RMSE** | 分别统计各场景绝对轨迹误差均方根，并按轨迹长度加权平均 |
| 辅助指标 | RPE | 补充比较局部运动估计稳定性 |
| 辅助指标 | 平移/旋转漂移 | 评估长序列累计漂移 |
| 辅助指标 | 建图一致性 | 结合可选地图文件评估局部/全局结构一致性 |
| 辅助指标 | 运行时间 | 辅助展示算法效率，必要时用于并列排序 |

### 并列处理

1. 若主排名指标完全相同，或差异小于 1%，依次比较 RPE、最大漂移、地图一致性和运行时间。
2. 若仍无法区分，组织方可结合可复现性材料、结果完整性和提交时间进行复核。

> 🔁 **提交次数限制：** 暂定每日最多 1 次、总计最多 5 次有效提交。最终排名以截止时间前最后一次有效提交为准；若后续规则调整，以最新通知为准。
