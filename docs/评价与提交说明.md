# 评价与提交说明

## 1. 提交格式

上传 ZIP 的根目录必须包含：

```text
README.md
trajectories/
├── scene_0001.txt
└── scene_0002.txt
```

轨迹采用 TUM 格式，每行八列：

```text
timestamp tx ty tz qx qy qz qw
```

时间单位为秒，位置单位为米，四元数顺序为 `[x,y,z,w]`。时间戳必须严格递增；
不允许重复、`NaN`、`Inf` 或零四元数。参赛者按 bag 中 LiDAR `header.stamp`
连续输出轨迹，不需要知道私有评测时间戳。

## 2. 时间关联和完成度

EVO 以最大 `0.05 s` 时间差，将提交轨迹与私有可靠真值一对一关联：

```text
completion = 匹配的可靠真值点数 / 全部可靠真值点数
```

完成度不设置硬性门槛，并在榜单公开。轨迹缺失部分会通过 AUC 的 recall 分母自然
扣分。两个 scene 文件仍然缺一不可，并且必须有足够关联点计算三档 RTE。

## 3. 对齐

每个 scene 独立执行一次无尺度 SE(3) 对齐，只估计旋转和平移，不估计尺度。
同一 scene 的全部有效匹配点共同计算一个对齐变换。

## 4. 精度指标

- **ATE**：EVO 平移 APE 的 RMSE，单位 m，越低越好。
- **AUC**：连续一帧平移 RPE 的 F1-AUC，范围 `[0,1]`，越高越好。
- **RTE**：在参考轨迹 1 m、5 m、10 m 距离上计算平移 RPE，并按距离归一化：

```text
RTE_pair(%) = translation_error_m / reference_distance_m * 100
```

聚合 ATE/RTE 是合并两个 scene 的原始误差后计算 RMSE，不是逐场景指标的算术平均。
综合 RTE 将 1 m、5 m、10 m 三档的全部有效归一化误差合并后计算 RMSE。平台同时
公开总体和逐场景的 `RTE@1m`、`RTE@5m`、`RTE@10m`，不会只公布综合 RTE。
每个 scene 都必须产生三个距离档的有效配对；周期性缺帧造成任一距离档无法计算时，
该提交无效。

## 5. 总分

公开参考结果用于确定误差归一化尺度：

```text
tau_ate_m   = 1.1542008644767718
tau_rte_pct = 33.05656442344478
```

```text
Total Score = 100 * (
    0.40 * AUC
  + 0.40 * exp(-ATE / tau_ate_m)
  + 0.20 * exp(-RTE / tau_rte_pct)
)
```

平台公开总分、聚合 AUC/ATE/综合 RTE、总体 RTE@1m/5m/10m、两个 scene 各自的
AUC/ATE/综合 RTE/RTE@1m/5m/10m，以及完成度和匹配数量。平台不公开真值、可靠
区间、评测时间戳、逐时刻误差或 EVO 对齐矩阵。

| 参考结果 | 综合 | scene_0001 | scene_0002 |
| --- | ---: | ---: | ---: |
| RTE@1m (%) | 52.102095 | 38.957570 | 65.354142 |
| RTE@5m (%) | 18.970067 | 14.748569 | 23.306717 |

## 6. 本地格式检查

公开评分代码位于 `scoring/`。本地检查只验证文件和 TUM 格式，不计算完成度或精度：

```bash
PYTHONPATH=. python3 -m scoring.validator \
  --submission /path/to/unzipped_submission \
  --config config/lidar_inertial.json
```

视觉赛道将配置替换为 `config/lidar_visual_inertial.json`。
